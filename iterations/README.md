# 迭代目录说明

本目录记录项目每次功能迭代的完整过程，帮助团队了解项目演进历程，为未来开发提供参考。

---

## 文件命名规则

```
ITERATION-<序号>-<简短描述>.md
```

- 序号为三位数字，从 `001` 开始按日期递增，**不可跳号**
- 简短描述使用中文，言简意赅
- **按天聚合**：同一天内的多次开发，统一记录到同一个迭代文件，不重复新建序号

**示例**：
```
ITERATION-001-项目初始化与首页.md
ITERATION-002-图片压缩工具.md
ITERATION-003-首页性能优化.md
```

---

## 迭代文档模板

每个迭代文件必须包含以下结构（可根据实际情况增减字段）：

```markdown
# ITERATION-XXX：标题

**迭代时间**：YYYY-MM-DD
**迭代类型**：新功能 / 功能增强 / Bug 修复 / 性能优化 / 重构
**影响范围**：列出受影响的文件或模块

---

## 背景与目标
> 简述为什么要做这次迭代，解决什么问题或满足什么需求。

## 新增 / 修改内容
- 功能点 1
- 功能点 2

## 涉及文件

| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| src/... | 新增     | ...  |
| src/... | 修改     | ...  |
| src/... | 删除     | ...  |

## 注意事项
> 上线注意事项、兼容性说明、已知问题等。

## 后续优化
> 本次未完成，留待后续迭代处理的事项。

## 当日更新记录（同日多次修改时必填）
- HH:mm - 调整点 A
- HH:mm - 调整点 B
```

---

## 使用规则

1. **按天聚合记录**：同一天内若已存在迭代文档，直接在该文件追加更新，不再新建新序号
2. **跨天新增文件**：仅当日期变化时新建下一序号文件，序号严格递增，不可跳号
3. **同日追加时允许修改当日文件**，但需在「当日更新记录」中写明新增调整点
4. **新增工具时**，必须同步：
   - 在 `docs/tools/` 下创建工具说明文档
   - 更新 `docs/README.md` 中的工具文档列表
   - 更新根目录 `README.md` 中的已有工具列表
5. **架构变更时**（新增依赖、调整目录结构、更换框架等），必须更新根目录 `README.md` 中的技术栈和项目结构章节
6. **Bug 修复**也需要记录，以便追溯问题来源
7. **完成迭代后**，同步更新本文件下方的迭代历史表格（同日追加无需新增行）
